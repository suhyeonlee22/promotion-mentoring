검증일: 2026-11-06 (KST). 기준 커밋: `7dd6b3f`.

최신 후속 검증은 **12절**을 참고한다. 현재 전체 자동 테스트는 **38파일 309개 PASS**, 빌드·수정 파일 ESLint PASS다. 설치된 headless Chrome의 실제 print 미디어에서 CSV/메뉴 숨김을 확인했다. 신청자별 실제 A4 출력은 여전히 미검증이다. 앞 절의 수치는 각 시점의 기록이다.

## 1. 판정 범위와 데이터 보존

- PASS는 아래에 명시한 자동 테스트 또는 코드 대조 범위의 판정이다. 실제 브라우저 인수 완료를 뜻하지 않는다.
- 최초 검증에서는 실제 브라우저 조작, 인쇄 미리보기/PDF, 키보드 조작, 화면 폭별 시각 검증을 수행하지 않았다. 이후 12절에서 headless Chrome의 실제 print 미디어 스타일만 추가 확인했다. 인쇄 대화상자/PDF·키보드·반응형·신청자별 출력은 계속 **미검증**이다.
- README Step 15와 요구사항 전체(특히 3~8장)를 대조했다. README의 개발 DB 초기화 지침보다 이번 사용자의 데이터 보존 지시를 우선했다.
- `db:reset`, `db:seed`, `db:passwords`, 개발 DB 대상 스키마 적용 명령은 실행하지 않았다.
- Vitest의 `DATABASE_URL=file:test.db`, `.env.test`, 파일 간 순차 실행 설정을 확인했다. 변경을 수반하는 검증은 `test.db`에서만 수행했다. 테스트 내 `seedAll()`은 이 격리 DB에만 실행된다.
- `npm test`의 준비 단계는 `.env.test`로 `drizzle-kit push --force`를 실행하며, 결과는 `No changes detected`였다. `local.db`를 대상으로 하지 않는다.
- 개발 DB와 부수 파일(`local.db`, `local.db-wal`, `local.db-shm`), `.env` 및 환경별 override 파일의 작업 전후 존재 여부·파일 내용 체크섬을 비교했고 모두 동일했다. 비밀번호·비밀키·저장된 비밀번호 해시는 출력하지 않았다.
- DB 스키마·패키지·인증·권한·업무 서비스·메일 발송 로직 변경 없음. Git 커밋 없음.

## 8. 사용자가 실제 브라우저에서 확인할 항목

1. `web/`에서 `npm run dev` 후 `/login`: HR/직원 로그인, 현재 이름·역할, 로그아웃, 잘못된 비밀번호, 직원 상태의 `/hr/...` 직접 접근 차단. 실제 비밀번호를 로그/보고서에 남기지 않는다.
2. `/me/promotion`: ERP 원본/현재 값과 승인·반려 배지, 입력 중 글자 수, 제출 실패 후 실적·계획·줄바꿈·오류 유지, 수정 후 재제출·임시저장. 검토 회차 미제출자는 작성 차단, 보완 요청자는 다시 작성 가능.
3. 회차→후보→신청 현황→상세→결과 이동, 사유/승인값/피드백 등 실제 FormData 연결과 오류 안내. 전체 흐름 재현은 별도 수동 검증 DB에서 한다.
4. 승급 목록 필터·상세 근거·자동/직접 확정·메일 발송 신규 목록. 변경을 수반하는 ERP 변경 4건 재현은 별도 DB에서 한다.

## 12. 인쇄 오류 재발 원인: CSS Modules 빌드 분류

사용자가 새로고침 후에도 CSV 영역이 인쇄된다고 보고해, 11절의 소스 검사만으로는 해결이 확인되지 않았음을 재확인했다. 이번에는 CSS 원본뿐 아니라 실제 Next/Turbopack 산출물의 클래스 맵과 CSS 선택자를 조사했다.

### 확인한 원인과 수정

- 기존 `next.config.ts`가 모든 `*.css`에 Tailwind 로더를 적용하고 `as: "*.css"`로 재분류했다. 이 규칙이 `review-data.module.css`에도 적용되어 CSS Modules의 기본 처리가 깨졌다.
- 수정 전 실제 서버 번들에서 해당 CSS import의 export가 **빈 객체 `{}`**인 것을 확인했다. JSX가 읽는 `styles.toolbar`, `styles.screenOnly`, `styles.sheet` 등의 값이 없어 DOM에 클래스가 제대로 연결되지 않았다.
- 같은 빌드의 CSS에는 `.toolbar`, `.screenOnly`, `.sheet` 같은 전역 이름이 출력됐다. 기존 인쇄 규칙이 있어도 DOM과 연결되지 않아 `!important` 보강으로 해결할 수 없었다. 전역 인쇄 CSS의 우선순위 충돌이 원인은 아니었다.
- Tailwind 로더 대상은 **`globals.css`만**으로 제한했다. CSS Modules는 Next의 기본 처리에 맡긴다. 패키지 추가/변경은 없다.
- 수정 후 빌드 CSS에서 `.<고유접두사>_toolbar`, `.<고유접두사>_screenOnly` 등 스코프 클래스가 생성되고 print 규칙에 연결되는 것을 확인했다. A4 named page·신청자별 페이지 분리·내용 줄바꿈 CSS는 변경하지 않았다.
- 확정 신청서 0건이면 기존처럼 앱 인쇄 버튼을 표시하지 않으며, “인쇄할 심사 자료가 없으므로 인쇄하지 마세요. 신청서 확정 후 인쇄할 수 있습니다.”라는 상태 안내를 추가했다. Ctrl+P 자체를 가로채거나 브라우저/OS의 인쇄 작업을 강제로 취소하지 않는다. 사용자는 안내에 따라 인쇄를 취소해야 한다.

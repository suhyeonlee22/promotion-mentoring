# 승진·승급 관리 시스템 배포 과정 기록

## 1. 배포 환경 설계 및 기술 선택

기존 승진·승급 관리 시스템은 Next.js와 로컬 SQLite 데이터베이스를 사용하여 개발되었다. 이번 과제에서는 로컬에서 실행하던 웹 애플리케이션을 외부에서도 접근할 수 있도록 배포하고, 실제 운영 환경에서 정상적으로 동작하는지 확인하는 것을 목표로 하였다.

호스팅 서비스는 Vercel, Render, Railway를 비교하였다. Next.js 프로젝트와 GitHub 연동이 편리하고 별도 서버 관리 부담이 적다는 점에서 **Vercel**을 선택하였다. 데이터베이스는 Turso, Supabase PostgreSQL, Neon PostgreSQL을 검토하였으며, 기존 SQLite 및 Drizzle ORM 구조를 최대한 유지하기 위해 **Turso**를 선택하였다.

최종적으로 GitHub에서 소스 코드를 관리하고, Vercel에서 애플리케이션을 배포하며, Turso에서 데이터를 저장하는 구조로 구성하였다.

## 2. 실제 배포 과정

먼저 로컬 SQLite를 사용하던 데이터베이스 연결을 배포 환경의 Turso에 맞게 구성하였다. 이후 Vercel 프로젝트에 `DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `CRON_SECRET` 환경변수를 등록하였다.

GitHub의 `main` 브랜치와 Vercel을 연동하여 코드 변경 사항을 배포하였다. 배포 전 자동화 테스트 309개와 프로덕션 빌드가 정상적으로 완료되는 것을 확인하였다.

배포 과정에서 Next.js 버전을 보안 패치가 적용된 16.4.6으로 변경한 적이 있었으나, 프로젝트의 기존 버전 유지 조건에 따라 16.4.3으로 복원하였다. 이 과정에서 버전 관리 조건과 보안 업데이트 필요성을 함께 고려해야 한다는 점을 확인하였다.

예약 작업은 Vercel Cron을 사용하여 매일 한국 시간 오전 9시에 실행하도록 설정하였다. Cron API에는 비밀값을 이용한 인증 검사를 적용하였으며, 관련 테스트를 확인하였다.

## 3. 배포 후 기능 및 보안 검증

실제 배포 사이트에서 HR 계정과 직원 계정으로 로그인하고, 로그아웃 후 보호된 관리자 페이지에 접근할 수 없는 것을 확인하였다.

HR 계정으로 테스트용 승진 회차를 생성하고 대상자 선정을 실행한 결과, **11명의 판정 대상 중 4명이 자동 선정**되었다. 이후 회차를 신청 상태로 전환하였으며, 직원 계정에서 해당 회차와 시스템 내부 신청 안내 메일이 표시되는 것을 확인하였다.

직원 계정으로 주요 업무실적과 자기개발 계획을 작성한 뒤 임시저장하였고, 페이지를 새로고침해도 내용이 유지되는 것을 확인하였다. 최종 제출 후에는 HR 계정에서 해당 신청서를 조회하고 확정할 수 있었다. 처리 이력에서도 신청서 생성, 임시저장, 제출, 확정 순서가 기록된 것을 확인하였다.

보안 측면에서는 로그인 세션 관리, 역할별 접근 제한, Cron API 인증 처리, 운영 환경의 개발용 기능 제한 등을 점검하였다.

## 4. 문제점 및 개선 사항

로컬 환경에서는 SQLite 파일을 직접 사용했지만, Vercel의 서버리스 환경에서는 로컬 파일에 데이터를 영구적으로 저장하기 어렵다는 문제가 있었다. 이를 해결하기 위해 SQLite와 호환되는 Turso를 선택하고 데이터베이스 연결 방식을 변경하였다.

또한 배포 과정에서 Next.js 버전을 변경하면서 프로젝트의 기존 버전 유지 조건과 보안 업데이트 사이에서 판단이 필요했다. 최종적으로 프로젝트 지침에 맞춰 16.4.3을 유지하되, 알려진 보안 취약점은 해결되지 않은 위험으로 기록하였다.

배포 후에는 REVIEWER 계정이 로그인 화면으로 돌아오는 현상을 발견하였다. 코드를 확인한 결과 역할별 이동 처리에 REVIEWER 분기가 없고, 해당 역할의 전용 화면은 P3 선택 기능으로 분류되어 있었다. 따라서 이번 필수 과제에서는 신규 기능을 구현하기보다 미구현 사항으로 기록하였다.

Vercel Cron은 설정과 인증 테스트를 확인했지만, 실제 예약 실행 기록은 무료 플랜의 로그 조회 범위 제한으로 확인하지 못하였다. 이를 통해 설정 완료와 실제 실행 검증을 구분해야 한다는 점을 배웠다.

## 5. 회고

이번 과제를 통해 로컬에서 프로그램이 실행되는 것과 실제 웹 서비스를 배포하여 운영하는 것은 다르다는 점을 배웠다. 특히 외부 데이터베이스 연결, 환경변수 관리, 인증 및 권한 검증, 예약 작업 설정 등 개발 단계에서 상대적으로 덜 고려했던 부분이 중요하다는 것을 알게 되었다.

또한 배포가 성공했다는 사실만으로 모든 기능이 정상 동작한다고 판단해서는 안 된다는 점을 느꼈다. 실제 사용자 역할에 따라 로그인하고, 데이터를 생성·수정·조회하면서 업무 흐름 전체를 검증하는 과정이 필요했다.

AI는 배포 과정에서 오류 원인을 분석하고 점검 순서를 정리하는 데 활용하였다. 다만 제안된 방법이 실제 프로젝트 구조나 Vercel 화면과 일치하지 않는 경우도 있어, 직접 코드와 실행 결과를 확인하며 판단하는 것이 중요하다는 점을 배웠다.

# ADR-001: 웹 애플리케이션 배포 환경 선택

- **상태:** 채택 및 배포 완료
- **작성일:** 2026-11-18
- **결정:** Vercel + Turso 사용

## 1. 배경 및 문제

기존 프로젝트는 로컬 Next.js 서버와 SQLite 파일(`local.db`)을 이용해 실행했다.

하지만 Vercel과 같은 서버리스 배포 환경에서는 로컬 파일을 영구적인 데이터베이스로 사용하는 것이 적합하지 않다. 실행 환경이 교체되거나 여러 인스턴스가 실행될 수 있기 때문이다.

따라서 웹 애플리케이션을 배포할 호스팅 서비스와 데이터를 지속적으로 저장할 외부 데이터베이스가 필요했다.

또한 환경변수, 초기 데이터, 예약 작업(Cron)을 배포 환경에서 관리할 방법도 고려해야 했다.

## 2. 호스팅 후보 비교

| 후보 | 장점 | 고려할 점 |
|---|---|---|
| Vercel | Next.js와 연동이 편리하고 GitHub 기반 자동 배포 지원 | 서버리스 실행 제약과 사용량 제한 |
| Render | 지속 실행 서버 구성 가능 | 서비스 설정 및 운영 관리 필요 |
| Railway | 다양한 백엔드 서비스와 DB 구성 가능 | 요금 및 사용량 관리 필요 |

**선택: Vercel**

프로젝트가 Next.js 기반이므로 배포 설정을 단순화할 수 있고, GitHub에 코드를 Push하면 자동으로 배포할 수 있다는 점을 고려했다.

예약 작업도 Vercel Cron으로 구성할 수 있어 별도 서버를 운영하지 않아도 된다는 장점이 있었다.

아래 비교는 각 서비스의 기술적 특성과 프로젝트 요구사항을 기준으로 검토한 결과이며, 모든 후보에 직접 배포하여 성능을 측정한 것은 아니다.

## 3. 데이터베이스 후보 비교

| 후보 | 장점 | 고려할 점 |
|---|---|---|
| Turso | SQLite 계열이며 기존 Drizzle ORM 구성과 연결하기 용이 | 외부 서비스 의존성 및 사용량 제한 |
| Supabase PostgreSQL | 관리형 PostgreSQL과 다양한 부가 기능 제공 | SQLite에서 PostgreSQL로 이전 작업 필요 |
| Neon PostgreSQL | 서버리스 PostgreSQL 제공 | 기존 SQLite 스키마 및 연결 코드 변경 필요 |

**선택: Turso**

기존 프로젝트에서 SQLite와 Drizzle ORM을 사용하고 있었기 때문에 데이터베이스 구조 변경을 최소화하는 방향을 선택했다.

Turso를 이용하면 배포 환경에서 외부 데이터베이스를 사용하면서 기존 SQLite 기반 구현을 상당 부분 유지할 수 있다.

## 4. 최종 배포 구조

| 구성 요소 | 선택한 환경 |
|---|---|
| 소스 코드 | GitHub |
| 웹 애플리케이션 | Vercel |
| 데이터베이스 | Turso |
| 환경변수 | Vercel 환경변수 설정 |
| 예약 작업 | Vercel Cron |
| 테스트 | Vitest |

## 5. 실제 배포 과정에서 확인한 사항

- 로컬 SQLite 파일 대신 Turso 데이터베이스를 연결했다.
- GitHub의 `main` 브랜치에 변경 사항을 Push하여 Vercel 배포를 진행했다.
- Next.js 16.4.6으로 업데이트한 뒤 프로젝트의 버전 유지 조건에 따라 16.4.3으로 복원하였다. 이후 자동화 테스트 309개와 빌드가 정상적으로 완료되었다. 다만 해당 버전의 알려진 보안 취약점은 잔여 위험으로 기록하였다.
- HR 계정과 직원 계정으로 로그인 및 화면 접속을 확인했다.
- 개발 전용 사용자 전환 페이지가 운영 환경에서 접근되지 않는 것을 확인했다.
- Vercel Cron을 매일 09:00(KST)에 실행하도록 설정하고 인증 처리 코드 및 테스트를 확인하였다. 실제 예약 실행 여부는 로그 조회 시간 제한으로 인해 확인하지 못하였다.
- README에 실행 방법과 배포 절차를 정리했다.
- 배포 환경에서 승진 회차 생성, 대상자 선정(11명 판정·4명 선정), 신청 상태 전환, 직원 신청서 임시저장 및 최종 제출, HR 신청서 조회 및 확정까지 확인하였다.


## 6. 예상되는 위험 및 한계

1. **외부 DB 의존성:** Turso 장애가 발생하면 DB 기능을 사용할 수 없다.
2. **사용량 제한:** Vercel과 Turso의 요금제별 사용량을 관리해야 한다.
3. **보안:** 배포 환경의 인증 토큰과 초기 계정 비밀번호를 안전하게 관리해야 한다. Next.js 16.4.3에서 알려진 보안 취약점이 확인되었으나, 프로젝트의 버전 유지 조건에 따라 이번 작업에서는 업그레이드하지 않았다. 운영 환경에서 지속 사용할 경우 보안 패치 적용이 필요하다.
4. **예약 작업:** Cron 실행 성공과 실제 업무 데이터 생성 여부를 구분해 확인해야 한다.
5. **검증 범위:** 로그인과 일부 화면 접속은 확인했으나, 모든 업무 기능의 운영 환경 동작을 검증한 것은 아니다.


## 7. 결정 결과

Vercel과 Turso를 사용하여 Next.js 애플리케이션을 실제 배포하는 데 성공했다.

로컬 환경과 배포 환경의 차이를 확인했고, 데이터베이스 연결 방식, 비밀값 관리, 예약 작업 구성 등을 검토하는 경험을 얻었다.

향후에는 주요 업무 기능과 예약 작업의 실제 데이터 처리 결과를 추가 검증할 예정이다.
